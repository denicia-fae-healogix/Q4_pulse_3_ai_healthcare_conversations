Do 3 independent coders read the path rules the same way?

What a pilot is, and why we run one

In step 11 we wrote rules (a codebook) for two columns of the flow chart:

  • Column 2: what the person did in their 2nd message.
  • Column 3: when they first shared background information.

Before using these rules on every chat, we test them on a small sample. This test is called a pilot. It tells us whether the rules are clear enough that different coders reach the same answer, and where they hesitate.

Column 1 (the opening request) is already final from step 10, so it is not part of this pilot.

Nothing is frozen or applied here. The suggested rule changes at the end are proposals for you to decide on.

How the pilot was done

  1. Sample. We picked 12 chats with a fixed random seed (12012), so the choice can be repeated.
    • Every opening group, every column-2 label and every column-3 label appears at least once.
    • The rest are close calls flagged in step 11.
    • Chats that stopped after one message were left out. There is no 2nd message to judge, and the computer finds them on its own.
  2. Coders. 3 fresh, independent coders each got the codebook and the full de-identified conversations.
    • Each coder saw the chats in a different shuffled order, with its own seed.
    • They never saw the step-11 draft labels.
  3. What each coder recorded for every label:
    • an exact quote from the participant’s message;
    • how sure they were (high, medium or low);
    • an “unclear because…” note when the rules did not decide the case.

Did the quotes check out?

Each quote was compared word for word with the message the coder named.

51 of 51 quotes matched exactly. So the coders were reading the real text, not inventing it.

Did the 3 coders agree?

Kappa (κ) is a score for agreement that allows for lucky guesses: 1 means perfect agreement, and 0 means no better than chance.

With only 12 chats, κ is a rough guide. One different answer would move it a lot.

agree |>
  mutate(fleiss_kappa = ifelse(is.na(fleiss_kappa) | fleiss_kappa == "", "–", as.character(fleiss_kappa))) |>
  select(`What was coded` = what, Chats = chats, `All 3 agree` = all_3_agree,

How sure were they?

Agreement is not the whole story. The coders were sure about column 2, but often only medium or low for column 3. That means the column-3 rules work, but some edges need clearer wording.

conf <- bind_rows(
  codes |> filter(col2_confidence != "") |> transmute(Column = "Column 2", conf = col2_confidence),
  codes |> filter(col3_confidence != "") |> transmute(Column = "Column 3", conf = col3_confidence)
) |>
  mutate(conf = factor(conf, levels = c("high", "medium", "low"))) |>
  count(Column, conf)

Column 2 matched the draft for all 12 chats. Column 3 differed for 2 chats:

  • 6a24b2df (weight-loss plan): the coders said After the AI asked; the draft said On their own later. The coders were right. The AI had asked for the current weight in a form, with no question mark, and the draft missed it. You approved fixing the draft (P9); it is now After the AI asked.
  • 671a8337 (“what if i am spitting blood”): the coders said On their own later; the draft said Never shared. The difference is whether a “what if” symptom counts as background. You decided a “what if” symptom is not background (P2), so it stays Never shared.
